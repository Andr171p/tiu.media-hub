# Ключевые решения

| Решение | Почему |
|---|---|
| Модульный монолит на DDF, use cases — функции | Одни и те же сценарии вызываются из HTTP, воркеров и (позже) MCP; меньше церемоний, явные зависимости |
| Коллекции плоские + подборки | Коллекция — граница доступа (одна у актива, права проверяются просто); подборки — курирование из разных коллекций и источник для порталов |
| Keycloak — только identity | Права на коллекции меняются часто и зависят от данных DAM; токен не должен их кешировать |
| Минимум статусов | Версия и актив создаются валидными; состояние обработки выводится из `processed_at`/`processing_error`, лицензии — из дат |
| Комментарии без формального согласования | Обсуждения с отметками, ответами и resolve закрывают сценарий согласования; отдельный агрегат Review можно добавить позже |
| Уведомления — позже | Место в архитектуре: доменное событие о комментарии и потребитель в relay; событие появится вместе с потребителем |
| RustFS + nginx как единая точка входа | MinIO больше не публикует образы; хранилище не торчит наружу, браузер ходит через nginx (presigned и подписанные ссылки CDN) |
| Два бакета | Оригиналы закрыты полностью, производные читает только CDN; разные политики проще, чем условия в одной |
| SHA-256 считает воркер | Хеш в браузере для видео в десятки ГБ слишком медленный; целостность загрузки — размер и ETag |
| Серверный рендер редактора по рецепту | Результат в разрешении оригинала, исходник не меняется, рецепт воспроизводим |
| TaskIQ + две очереди | Перекодирование видео (CPU) не задерживает поиск и ИИ (сеть/GPU), и наоборот |
| Transactional Outbox для событий | Изменения и задачи на их обработку не расходятся при сбоях |
| CLIP в Infinity, лица OpenCV YuNet + SFace | Лицензии допускают использование (SFace/YuNet — Apache-2.0/MIT; InsightFace — только некоммерческое), работают на CPU |
| Гибридный поиск через RRF | CLIP находит смысл без описаний, полнотекстовый поиск по ИИ-описанию и речи точнее; RRF не требует калибровки оценок |
| Профили compose cpu/gpu | Одна команда запуска; переключение строкой в `.env`, у вариантов одинаковые сетевые имена |
| VLM через OpenAI-совместимый API | В разработке — дешёвая модель AITunnel, на сервере — локальная Ollama без изменений кода |
| Чистая схема БД | Данные старой реализации не переносятся; старый код — в `legacy/` до удаления |

## Известные ограничения

* Качество text-to-image ограничено CLIP ViT-B/32. На GPU-сервере можно взять более сильную модель
  (подобрать пороги и пересоздать `dam_visual`).
* Ошибка рендера в редакторе не видна пользователю (задача повторяется, затем уходит в dead letter):
  фронт ждёт результат по `versionId` ограниченное время.
* Поиск коллег — по профилям тех, кто уже входил; поиск по всему Keycloak — через Admin API (не реализован).
* Правки DDF, обойдённые локально (предложены к внесению в DDF):
  `S3Client` подписывает presigned URL устаревшей SigV2 (нужен `signature_version="s3v4"`),
  `SqlAlchemyRepository.exists()` строит невалидный SQL на SQLAlchemy 2.1.
