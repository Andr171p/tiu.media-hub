# Доменная модель

Принципы: объекты создаются сразу валидными, статусов почти нет (состояние выводится из полей),
value objects — только там, где у значения есть смысл и правила.

## Коллекции (`domain/collections`)

* **Collection** — граница доступа: `owner_id`, `visibility` (`private` | `internal` — все сотрудники читают),
  `upload_policy` (MIME-маски и лимит размера), `metadata_schema` (кастомные поля: text, number, date,
  boolean, choice). Инвариант: ключи полей схемы уникальны.
* **CollectionMember** — участник с ролью `viewer` | `editor` | `manager`. Владелец участником не хранится.
* `resolve_permissions()` — права пользователя: `read`, `write`, `manage`, `own` (см. [доступ](access.md)).
* Удалить можно только пустую коллекцию (ограничение и в БД: `RESTRICT`).

## Активы (`domain/assets`)

* **Asset** — единица контента в одной «домашней» коллекции: title, description, `caption` (описание от ИИ),
  `tags`, `metadata` (по схеме коллекции), `license`, `current_version_id`, `version_count`.
  * `add_version()` — новая версия того же вида (`accepts()`: фото → фото), сразу текущая;
  * `make_current()` — откат к версии этого актива.
  * Теги, описание, лицензия меняются обычным обновлением: для домена не важно, кто добавил тег.
  * Перенос, корзина, восстановление — доменные функции с событиями для поискового индекса.
* **AssetVersion** — неизменяемый файл (`StoredFile`: ключ, имя, MIME, размер). Обработка дописывает
  `meta` (размеры, длительность, кодеки, страницы, EXIF), `renditions`, `sha256`, `processed_at`,
  `processing_error`. Статус для API выводится: нет `processed_at` — обрабатывается, есть ошибка — failed.
  `source_version_id` — из какой версии получена правка редактора.
* **Rendition** (VO) — производная: `thumbnail` (~480px WebP), `preview` (~2048px WebP; постер видео,
  первая страница PDF), `video` (720p H.264), `audio` (AAC).
* **License** (VO) — тип, правообладатель, `period` (start/end), территории, носители, ограничения.
  `status(today)` вычисляется: `active`, `expiring` (≤30 дней), `expired`, `not_started`.
* **Upload** — сессия загрузки по presigned URL (multipart для больших файлов). После подтверждения
  удаляется; версия получает `id` загрузки, поэтому подтверждение идемпотентно.

## Люди (`domain/people.py`)

* **Person** — человек из справочника (name, description).
* **Face** — лицо на версии актива: `box` (доли кадра), `timecodes` (для видео — появления человека),
  `person_id`, `assigned_by` (кто подписал; `None` — распознано автоматически).
  * `assign()` — ручная подпись, событие `FaceAssigned`;
  * `match()` — автоматическое распознавание, не перезаписывает ручную подпись.
* Вектор лица хранится в Qdrant под `id` лица.

## Комментарии (`domain/comments.py`)

* **Comment** — к версии актива; корневой комментарий — обсуждение, ответы — один уровень.
  `anchor`: `Region` (область изображения) или `TimeRange` (момент/отрезок видео).
  `resolve()`/`reopen()` — только для обсуждения.
* Уведомлений пока нет: событие для них появится вместе с потребителем (см. [решения](../decisions.md)).

## Подборки (`domain/selections.py`)

* **Selection** — упорядоченный список активов из разных коллекций (до 1000), `shared` — видна всем.
  Пользователь видит в подборке только активы доступных ему коллекций.

## Порталы (`domain/portals.py`)

* **Portal** — мини-сайт: slug, title, `theme` (цвет, логотип, обложка), `blocks`, `access`
  (`public` | `password` | `employees`), `allow_download`, `published_at`.
* Блоки: `hero`, `text` (markdown), `gallery` (коллекция или подборка + фильтр по тегам — всегда актуальна),
  `files` (список для скачивания).
* Инварианты: у галереи ровно один источник; для доступа по паролю пароль обязателен.

## Пользователи (`domain/users.py`)

* **User** — профиль из токена Keycloak (`id` = `sub`): для авторов, участников и поиска коллег.
  Обновляется при запросах (не чаще раза в 15 минут на процесс).
