# Медиа: загрузка, обработка, раздача

## Хранилище

RustFS (S3), два бакета:

| Бакет | Содержимое | Доступ |
|---|---|---|
| `dam-originals` | Оригиналы и результаты редактора (`YYYY/MM/<id>.<ext>`) | Только presigned URL (загрузка, скачивание) |
| `dam-renditions` | Производные (`<version_id>/<kind>.<ext>`), миниатюры лиц (`faces/<face_id>.webp`) | Анонимное чтение внутри сети Docker; снаружи — только через nginx по подписи |

В БД хранятся ключи объектов, а не ссылки. Ссылки выдаются в момент ответа.

## Загрузка

1. `POST /api/v1/uploads` — проверка прав (`write`) и правил коллекции (MIME, размер). Ответ:
   * до 100 МБ — одна PUT-ссылка и заголовки (`Content-Type` входит в подпись);
   * больше — multipart: ссылки на части по 64 МБ (до 10 000 частей, т. е. файлы в сотни ГБ).
2. Браузер загружает файл напрямую в хранилище через nginx (`/dam-originals/...`); API не пропускает
   через себя содержимое.
3. `POST /api/v1/uploads/{id}/complete` (для multipart — с ETag частей): размер сверяется с заявленным,
   в одной транзакции создаётся актив (или новая версия) и событие обработки. Повтор возвращает тот же актив.

Брошенные загрузки удаляет планировщик (сессия живёт 6 часов). SHA-256 считается воркером при обработке —
не в браузере (видео в десятки гигабайт).

## Обработка (`worker-media`)

| Вид | Метаданные | Производные |
|---|---|---|
| Изображение (вкл. HEIC) | размеры с учётом EXIF-поворота, дата съёмки, камера | `thumbnail`, `preview` (WebP) |
| Видео | размеры с учётом поворота, длительность, fps, кодеки | постер → `thumbnail`/`preview`, `video` 720p H.264 + AAC, faststart |
| Аудио | длительность, кодек | `audio` AAC |
| PDF | число страниц | первая страница → `thumbnail`/`preview` |
| Прочее | — | — (только скачивание) |

Повреждённый или неподдерживаемый файл не ломает актив: версия получает `processingError`
и остаётся доступной для скачивания. Администратор может запустить обработку заново:
`POST /api/admin/v1/versions/{id}/reprocess`.

После обработки (`worker-ai`): CLIP-векторы кадров, лица, описание и теги от VLM (фото, видео),
расшифровка речи (видео, аудио). Для видео кадры берутся равномерно из прокси (до 24 кадров).

## Раздача (nginx CDN)

* Ссылки на производные подписывает бэкенд: `/media/<key>?expires=…&token=md5(expires + uri + secret)`.
  Срок округляется до окна (`CDN_URL_TTL`, 1 час): ссылка стабильна в окне и кешируется браузером.
* nginx кеширует ответы хранилища кусками по 1 МБ (`slice`): перемотка видео (Range) тоже идёт из кеша.
* Неверная подпись — 403, просроченная — 410.
* Оригиналы скачиваются по presigned URL с `Content-Disposition: attachment` и исходным именем файла.

## Редактор изображений

Фронт собирает **рецепт** и показывает предпросмотр на canvas по превью. Сервер применяет рецепт к
оригиналу в полном разрешении (Pillow): поворот/отражение → кадрирование → размер → яркость, контраст,
насыщенность → фильтр (`grayscale`, `sepia`, `warm`, `cool`, `vintage`) → текст. Координаты — доли кадра,
поэтому одинаковы для превью и оригинала.

`POST /api/v1/assets/{id}/edits` отвечает `202` с `assetId` и `versionId` результата
(`saveAs: version` — новая версия, `asset` — новый актив в той же или другой коллекции).
Оригинал не меняется; у результата `sourceVersionId` указывает на исходную версию.

## Водяные знаки (запланировано)

Место в архитектуре: вариант производной с суффиксом ключа (`<version_id>/preview-<variant>.webp`,
см. `rendition_key`) и выбор варианта в `presenters.py` — единственном месте, где ключи превращаются
в ссылки. Настройка — в `Collection` рядом с `upload_policy`.
